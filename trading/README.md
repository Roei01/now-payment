# מערכת תיקי דמה ותיק מסחר חי

אפליקציית Web מותאמת למובייל (PWA, עברית RTL) שמריצה שלוש אסטרטגיות בשלושה תיקי דמה מבודדים (200 ₪ כל אחד), מודדת אותן מול מדד ייחוס, ומחזיקה תיק חי **רדום** שלא שולח פקודות עד שמתקיימים כל התנאים.

> זה תכנון הנדסי, לא הבטחה לתשואה. רווח בתיק דמה אינו מוכיח רווח בתיק אמיתי.

## מה יש בפנים

| רכיב | קבצים | תפקיד |
|---|---|---|
| סכמה | `migrations/001_init.sql` | כל הטבלאות מהאפיון. `ledger_entries`, `fills`, `order_events`, `audit_events`, `strategy_versions`, `live_policy_versions`, `forecast_snapshots` מוגנות מפני שינוי ומחיקה בטריגר |
| נתוני שוק | `src/market/*` | Alpaca (IEX/SIP), שער USD/ILS מ־Frankfurter (ECB), ספק מדומה לפיתוח. כל batch נשמר עם זמן פרסום, זמן קליטה וזמינות |
| יסודות חברה | `src/research/edgar.ts` | SEC EDGAR point-in-time: נעשה שימוש רק בדוחות שהוגשו לפני זמן ההחלטה |
| אסטרטגיות | `src/strategies/*` | מומנטום בקרנות סל, תיק הגנתי עם איזון, "מתחת לשווי" עם מנהל AI, ו־SPY פסיבי כמדד ייחוס |
| מנהל AI | `src/ai/*` | Claude עם פלט JSON מובנה, אימות סכמה ומקורות, מעקב עלויות מול תקרה חודשית, ודחייה (HOLD) כשחסר מידע או תקציב. בלי שדרוג שקט למודל חלש |
| שער סיכון | `src/risk/*` | רשימת נכסים מאומתת (ללא מינוף, ללא מוצר הפוך, ללא קריפטו), קנייה במזומן בלבד, בלי שורט, מגבלות ריכוז, מבחני לחץ שמחושבים בקוד מול יעד של 30% מההון ההתחלתי, חסימת מיצוע כלפי מטה, שוק סגור ומחיר ישן. בלי stop-loss אוטומטי |
| ביצוע | `src/execution`, `src/broker` | שמירה לפני שליחה, `client_order_id` דטרמיניסטי, בדיקה אצל הברוקר לפני כל שליחה חוזרת, fills אידמפוטנטיים, פיוס אחרי restart, השהיה כשתשובת הברוקר לא ודאית או כשיש פער בפוזיציות |
| מחזור | `src/engine/cycle.ts` | snapshot, פיוס, אסטרטגיה, (AI), סיכון, ברוקר, ספר חשבונות, ביצועים. HOLD היא תוצאה תקינה |
| למידה | `src/learning`, lessons/experiments | תחזית נשמרת לפני התוצאה ומוערכת כשהאופק מבשיל. לקחים הם מועמדים עד שמאשרים אותם, וכל ניסוי נרשם, גם אם נכשל |
| Backtest | `src/backtest/*` | דטרמיניסטי, בלי look-ahead, עם חלוקה לתקופת פיתוח ולתקופת בדיקה. מסרב להריץ אסטרטגיה שתלויה ב־AI (סכנת זליגת ידע עתידי) |
| שער קידום | `src/promotion/*` | ימי forward, מספר עסקאות, נתונים אמיתיים, כיסוי, DD, תשואה עודפת, מובהקות עם תיקון Bonferroni, יציבות בין תקופות |
| לייב | `src/live/*` | ‎DORMANT→ELIGIBLE (מערכת בלבד)→ARMED→PILOT→ACTIVE, ומכל מצב אפשר PAUSED. מדיניות חתומה עם 2FA, בדיקת מוכנות ו־`LIVE_TRADING_ENABLED` |
| שרת/UI | `src/server`, `web/` | סיסמה + TOTP, סשן HttpOnly, CSRF, נעילה אחרי ניסיונות כושלים, תפקידי owner/viewer ו־audit. מסכים: סקירה, תיק, החלטות (trace מלא), אסטרטגיות, לייב, תפעול והגדרות |
| Worker | `src/worker/*` | מחזור כל שעה בזמן מסחר ועוד מחזור אחרי הסגירה, פיוס, watchdog לנתונים ישנים, ג׳ובים יומיים (שער, תחזיות, זכאות), סיכום יומי ותור דוא״ל. advisory locks ו־graceful shutdown |

## הרצה מקומית

```bash
cd trading
npm ci
cp .env.example .env        # מלאו DATABASE_URL, APP_SECRET, SETUP_TOKEN
set -a; . ./.env; set +a
npm run migrate:dev && npm run seed:dev
npm run dev:api             # http://localhost:3000
npm run dev:worker          # בטרמינל נפרד
npm run dev:web             # UI עם hot reload ב־5173 (proxy ל־API)
```

בכניסה הראשונה המסך מבקש את `SETUP_TOKEN` ויוצר משתמש בעלים. אחר כך מפעילים 2FA במסך הגדרות: בלי 2FA פעולות רגישות חסומות.

כלים נוספים: `npx tsx src/scripts/run-cycle.ts [ISO-time]`, `npm run backtest:dev -- TREND_ROTATION 2025-01-01 2026-09-01 DEV`.

## בדיקות

```bash
TEST_DATABASE_URL=postgres://... npm test      # 47 בדיקות: יחידה ואינטגרציה מול Postgres אמיתי
npm run typecheck
```

הבדיקות מכסות: וקטורי RFC ל־TOTP, כללי הסיכון (מזומן, שורט, מינוף, נכס לא מאומת, שוק סגור, מחיר ישן, kill switch, תקציב סיכון, מיצוע כלפי מטה, שברים), שער הקידום, דטרמיניזם של ה־backtest והיעדר look-ahead, בלתי־ניתנות לשינוי של הספר, fill כפול, retry בלי כפל פקודה, קריסה בין submit ל־ack ושחזור, פער פוזיציות שגורם להשהיה, תיק לייב שלא ניתן לדרוך בלי 2FA ובלי מוכנות, CSRF, 2FA, נעילה אחרי ניסיונות כושלים, סירוב לפלט AI שמצטט מקור לא קיים, ומרווח ביטחון שמחושב בקוד.

## פריסה ב־Render

`render.yaml` בשורש המאגר יוצר את `trading-web`, את `trading-worker` ואת `trading-db`. אחרי יצירת ה־Blueprint מזינים בלוח הבקרה את הסודות המסומנים `sync: false`. המיגרציות רצות אוטומטית בעליית כל שירות (תחת advisory lock ודגל maintenance שחוסם פקודות).

## נתונים אמיתיים, הון מתמשך וריצות

- **בפרודקשן הנתונים תמיד אמיתיים.** השרת מסרב לעלות עם מחירים מדומים או עם שער מט״ח קבוע, אלא אם מוגדר במפורש `ALLOW_SIMULATED_DATA=true`, וזה מיועד להדגמה בלבד.
- **תיקי הדמה מבצעים עסקאות מדומות, על מחירים אמיתיים.** הביצוע נעשה בסימולטור פנימי, לפי ציטוטי Alpaca בזמן אמת, עם החלקה ועמלות.
- **ההון לא מתאפס.** 200 ₪ מומרים פעם אחת, בשער מתועד, כשהתיק נוצר. מאותו רגע השווי מתעדכן מתוך ספר החשבונות. הפעלה מחדש, deploy או הוספת מפתחות לא מאפסים אותו.
- **כל ריצה קשורה למקור הנתונים שעליו התחילה.** אם המקור משתנה, למשל ממדומה לאמיתי, המסחר בריצה נעצר, נפתחת תקלה ונשלחת התראה. שום דבר לא מתאפס לבד.
- **ריצה חדשה נפתחת רק בהחלטה שלכם**, עם 2FA, במסך התיק. הריצה הקודמת עוברת לארכיון עם כל ההיסטוריה.
- **התיק החי רץ במקביל על אותם נתונים.** ההון ההתחלתי שלו נלקח מהמזומן בחשבון הברוקר האמיתי בתחילת הפיילוט, ומוגבל לתקרה שבמדיניות החתומה.

## החלטות זמניות שממתינות לאישורכם

- **נקודת הייחוס ל־30%**: כרגע המדידה היא מההון ההתחלתי בדולרים, ובמסך מוצגים גם הפסד מההון וגם ירידה מהשיא. זה מסומן כזמני.
- **ערכי שער הקידום** (90 יום, 6 עסקאות, DD ‏20%, alpha 5%): ערכי דיון, לא סופיים.
- **הנחות עלות**: Alpaca בלי עמלה, עמלה רגולטורית קטנה במכירה, החלקה של 5bps והמרת מט״ח של 25bps. לא אומתו מול חשבון.
- **פרמטרי האסטרטגיות** (למשל מרווח ביטחון של 20% וסינון של 15% מתחת לשיא): פרמטרי מחקר התחלתיים שלא אומתו.
- **שאלה 14, מי משתמש באתר**: כרגע בעלים יחיד, עם אפשרות למשתמשי צפייה בלבד. אין תמיכה בניהול כספים של אחרים.
